在三维游戏中，一个物体能够被看见、呈现不同的表面质感，并随着动作改变姿态，背后需要多种资源与程序配合。本文以 Unreal Engine（UE）的常见概念为基础，介绍模型、网格、材质、纹理、骨骼与着色器的分工，不需要预先了解具体工程或代码。

## 1. 六个概念先放在一起看

| 名称 | 中文 | 核心职责 | 角色或木箱示例 |
| --- | --- | --- | --- |
| Model | 模型 | 对三维对象或其资源集合的宽泛称呼，范围取决于工具和引擎 | 一个角色模型、一套木箱资源 |
| Mesh | 网格 | 描述几何形状，通常包含顶点、索引以及法线、UV 等属性 | 角色表面或箱子的三角形 |
| Material | 材质 | 定义表面如何渲染，组织参数、纹理及着色逻辑 | 木头、金属、皮肤的表面表现 |
| Texture | 纹理／贴图 | 存储供渲染读取的数据，不局限于颜色图片 | 木纹、法线、粗糙度、遮罩 |
| Skeleton | 骨骼 | 定义骨骼层级和参考姿态等，配合动画与蒙皮驱动网格 | 肩膀、手臂、手指的骨骼 |
| Shader | 着色器 | 在 GPU 上运行的程序，执行顶点、像素或计算任务 | 顶点变换、纹理采样、表面着色 |

这些词都不是需要展开的首字母缩写。尤其 Mesh 本身就是英文单词，意思是“网格”。

## 2. Model 与 Mesh：整体称呼和几何数据

### 2.1 Model 没有统一的资源边界

“交付一个模型”可能只指几何网格，也可能包含网格、材质、纹理、骨骼等配套内容。动画有时一起交付，有时单独管理。

因此，不应将 Model 定义成固定公式，也不能假定每个模型都有骨骼。具体范围要看资源格式、引擎类型和团队约定。

### 2.2 Mesh 描述形状

游戏中的网格通常以三角形表达表面，常见数据包括：

- 顶点位置：几何形状的基础。
- 索引：哪些顶点组成一个三角形。
- 法线、切线：支持表面方向与法线贴图等计算。
- UV：纹理坐标，用于将纹理数据映射到表面。
- 顶点颜色：可作为颜色、遮罩等附加数据。

一个立方体有 8 个几何角点，6 个面可以拆为 12 个三角形。但实际渲染顶点数不一定是 8：不同面可能需要不同法线和 UV，因此同一个位置可能对应多个顶点记录。

### 2.3 Static Mesh 不等于不能动

| 类型 | 主要特点 | 示例 |
| --- | --- | --- |
| Static Mesh | 通常不依靠骨骼蒙皮变形 | 箱子、石头、建筑 |
| Skeletal Mesh | 包含支持骨骼蒙皮的数据 | 人物、动物 |

静态网格可以整体移动、旋转、缩放，也可以参与物理模拟。它还可以通过材质等途径产生顶点位移。因此，“Static”不能简单理解为位置固定或永远不变形。

## 3. Material 与 Texture：表面规则和输入数据

### 3.1 Material 定义表面表现

以常见的基于物理的渲染（PBR）材质为例，材质会涉及基础颜色、金属度、粗糙度、法线、自发光等输入，以及不透明／透明等渲染设置。

同一个立方体网格，配不同材质，可以呈现为木箱、金属块或塑料块。几何形状可以完全相同，表面表现却不同。

一个 Mesh 也可以有多个材质槽，例如角色身体使用皮肤材质，衣服使用布料材质。材质槽通常与网格的 section 等划分关联，但不宜把材质槽数直接等同于最终绘制调用数。

### 3.2 Texture 不只是彩色图片

| 常见纹理用途 | 存储的主要数据 |
| --- | --- |
| Base Color | 表面基础颜色 |
| Normal | 编码后的法线方向信息 |
| Roughness | 表面粗糙度 |
| Metallic | 金属度 |
| Mask | 区域权重、混合权重等 |

多个标量数据可以分别打包到同一纹理的不同通道中。读取时，需要按照资源约定解释这些数据。

UV 可以理解为表面上的“取样地址”。Shader 通过纹理采样操作，根据坐标和采样规则获取数据；材质决定如何使用这些结果。

材质不一定使用纹理。纯色可以来自常量参数，条纹、噪声等也可以由程序计算。

## 4. Skeleton：骨骼、动画与蒙皮的分工

Skeleton 描述骨骼层级，例如上臂连接前臂，前臂连接手掌。它本身不是角色表面，也不等于动画。

| 内容 | 职责 |
| --- | --- |
| Skeleton | 定义骨骼关系和参考姿态等 |
| Animation | 描述姿态随时间的变化 |
| 蒙皮权重 | 描述每个顶点受哪些骨骼影响、影响多少 |
| Skeletal Mesh | 提供几何表面以及蒙皮所需数据 |

角色抬手时，动画系统计算骨骼姿态，蒙皮计算再依据骨骼变换和顶点权重改变网格顶点位置。

骨骼通常以编辑器辅助线的形式显示；真正渲染出的角色表面来自网格和材质。骨骼也可以被程序或物理系统驱动，不只依赖预制动画。

## 5. Shader：执行计算的程序

Shader 不只是“给模型上颜色”。不同阶段的 Shader 承担不同工作：

| 常见种类 | 典型工作 |
| --- | --- |
| Vertex Shader | 顶点变换，输出后续光栅化需要的数据 |
| Pixel / Fragment Shader | 纹理采样、表面计算，输出颜色或中间渲染数据 |
| Compute Shader | 通用 GPU 计算，如模拟、数据处理、图像处理 |

具体光照计算在哪个阶段执行，取决于渲染路径。例如延迟渲染中，表面阶段可能先写入中间缓冲，再由后续阶段完成光照。

Texture 是输入数据，Shader 是处理数据的程序，Material 则提供表面表达及配置。三者紧密配合，但不是同一个概念。

在 UE 的常见工作流中，开发者连接材质节点、设置参数，由引擎编译出所需的 Shader。一个材质可能对应多个渲染 pass 和多个 Shader 变体，不能机械理解成“一个 Material 等于一个 Shader 程序”。

## 6. 整体关系

下表表达常见的使用关系，不表示所有引擎必须采用相同的对象所有权结构。

| 关联概念 | 关系 |
| --- | --- |
| Model 与 Mesh、Material、Skeleton | Model 是整体资源的宽泛称呼，可能包含网格、材质和骨骼等内容，具体范围依赖语境 |
| Material 与 Texture | 材质使用纹理提供的采样数据，组织表面表现 |
| Material 与 Shader | 材质表达与渲染需求共同决定所需的 Shader，由 GPU 执行相关计算 |
| Skeleton 与蒙皮 | 骨骼姿态配合顶点权重，为蒙皮计算提供输入 |
| 蒙皮与 Mesh | 蒙皮计算改变网格顶点位置，使表面随姿态变化 |

木箱通常用不到骨骼：网格提供箱子形状，纹理提供木纹数据，材质定义粗糙程度等表面属性，Shader 执行相应计算。

角色通常还需要骨骼、蒙皮权重和动画。它们解决姿态变化问题，与材质如何呈现皮肤、衣服属于不同职责。

## 7. 在 UE 中，这些概念如何落地？

### 7.1 资源和场景中的物体不是一回事

网格、材质、纹理和骨骼通常以资源的形式保存。资源可以被重复使用，而场景中的每一个物体都有自己的位置和状态。

例如，一条街上的十个路灯可以共享同一份静态网格和材质，不必制作十份相同的模型。它们各自使用网格组件，把共享的几何资源放到不同的位置。

| UE 中常见的名称 | 对应含义 |
| --- | --- |
| Static Mesh | 静态网格资源，如路灯、石头、桌子 |
| Skeletal Mesh | 骨骼网格资源，如人物和动物 |
| Material | 定义表面表现的材质资源 |
| Material Instance | 复用父材质，并覆盖其开放参数的材质实例 |
| Texture | 提供颜色、法线、遮罩等数据的纹理资源 |
| Skeleton | 定义骨骼层级等信息的骨骼资源 |
| Mesh Component | 在场景中使用网格资源的组件 |

一个组件可以尚未绑定网格；多个组件也可以共享同一个网格。共享网格并不要求物体处在相同的位置，也不要求它们使用完全相同的材质配置。

### 7.2 材质实例让外观变化更方便

假设有一套汽车漆材质，已经定义好了颜色、粗糙度和金属度的计算方式。制作红色和蓝色汽车时，可以创建不同材质实例，分别设置颜色参数，而不必重做整套材质逻辑。

材质实例与纹理不是同一种东西：前者保存材质参数的配置，后者提供被采样的数据。材质实例也不等于一份独立编写的 Shader；它如何影响 Shader 编译和复用，取决于参数类型与具体设置。

### 7.3 材质节点与 Shader 的关系

UE 的材质编辑器允许使用节点表达计算，例如读取一张纹理、将颜色乘以一个参数，再连接到表面属性输入。

这些节点是开发者描述表面效果的方式。引擎会结合渲染需求，将相关表达编译成 GPU 可以执行的 Shader。材质图不是一张模型贴图，节点也不是直接在屏幕上绘制物体的几何图形。

## 8. 常见误区与自测

| 常见误区 | 更准确的理解 |
| --- | --- |
| Model 必然等于 Mesh | Model 是更宽泛、依赖语境的称呼 |
| Static Mesh 不能移动 | 可以整体运动，通常不依赖骨骼蒙皮 |
| 网格组件创建后一定有模型 | 组件可以存在而网格资源为空 |
| Texture 就是模型颜色 | 也能存储法线、粗糙度、遮罩等数据 |
| Material 就是一张贴图 | 材质组织着色逻辑、参数和纹理等 |
| Skeleton 就是动画 | 骨骼定义结构，动画描述姿态随时间的变化 |
| Shader 只负责最终颜色 | 还可负责顶点处理、计算任务等 |

自测：

1. 同一个立方体网格能否显示成木头和金属？——能，为不同组件设置不同材质即可。
2. 两个组件共享一个 Mesh，是否必须在同一位置？——不必，组件变换独立。
3. 不用 Texture 能否渲染物体？——能，例如使用常量颜色的材质。
4. 只提供 Skeleton 能否显示完整角色？——不能，还需要可渲染的几何表面等内容。
5. 改变汽车的车漆颜色是否一定要重做网格？——不需要，通常调整材质或材质实例即可。
